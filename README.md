We are building a full-stack web application called “SkillSwap” based on the 16 UI screens imported from Stitch.

IMPORTANT:

Use the imported Stitch screens as the visual source of truth.

Do NOT redesign the UI.

Do NOT replace the existing design with a generic template.

Do NOT remove or rename the existing screens.

Maintain the same:

- colors

- typography

- spacing

- cards

- buttons

- navigation

- icons

- responsive layouts

- visual hierarchy

PROJECT PURPOSE:

SkillSwap is a community skill-exchange platform where users can teach skills they already know and learn skills they want to learn.

Users should be able to:

- Create an account

- Login/logout

- Create and edit their profile

- Add skills they offer

- Add skills they want to learn

- Set availability

- Set profile visibility

- Explore other users

- Find smart skill matches

- Send swap requests

- Accept/reject swap requests

- Manage active swaps

- Complete swaps

- Give ratings and feedback

- Receive notifications

- Manage account settings

Admins should be able to:

- View/manage users

- Ban/unban users

- Monitor swap requests

- Manage skills

- Review reports and feedback

- Send platform-wide announcements

- View activity statistics

TECHNOLOGY:

Use:

- React

- TypeScript

- Tailwind CSS

- Supabase

SUPABASE IMPORTANT:

An existing Supabase project is already connected.

Use the EXISTING Supabase database.

DO NOT create a new Supabase project.

DO NOT recreate or duplicate existing tables.

DO NOT create a separate users table.

DO NOT create a password column in profiles.

Existing database tables are:

profiles

skills

user_skills

swap_requests

ratings

notifications

Supabase Authentication must be used for user registration, login and logout.

The profiles table is linked to Supabase Auth users.

Existing profile fields include:

- id

- name

- email

- profile_photo

- location

- bio

- availability

- is_public

- role

- rating

- created_at

Existing skills include skills such as:

React, JavaScript, HTML, CSS, Python, Java, Excel, PowerPoint,

Photoshop, Canva, Graphic Design, Video Editing, Photography,

Digital Marketing, Social Media Marketing, Content Writing,

English, Gujarati and Hindi.

ROUTES:

Create/maintain these routes based on the imported Stitch screens:

/

 /explore

 /user/:id

 /login

 /register

Authenticated:

 /dashboard

 /profile

 /profile/edit

 /skills

 /matches

 /swap-requests

 /my-swaps

 /notifications

 /settings

Admin:

 /admin

 /admin/users

 /admin/swaps

 /admin/skills

 /admin/reports

 /admin/announcements

AUTHENTICATION:

Implement Supabase authentication.

Registration should collect:

- Full Name

- Email

- Password

- Confirm Password

- Location (optional)

- Profile Photo (optional)

After successful registration:

- Sign the user in

- Redirect to the Dashboard

- Use the existing Supabase profile creation trigger if available

- Never store passwords in the profiles table

Login should:

- Authenticate using Supabase Auth

- Redirect authenticated users to /dashboard

- Show proper validation and error messages

Logout should:

- Sign the user out through Supabase

- Redirect to the landing page

ROUTE PROTECTION:

Unauthenticated users must not access authenticated pages.

Admin pages must only be accessible to users whose profiles.role is “admin”.

Do not expose admin functionality to normal users.

PROFILE:

Connect the imported Profile UI to the existing profiles table.

Users must be able to:

- View their profile

- Edit name

- Edit location

- Edit bio

- Upload/change profile photo

- Set availability

- Set public/private visibility

Use Supabase Storage for profile photos if storage is available/configured.

SKILLS:

Connect the profile skill sections to:

- skills

- user_skills

Users must be able to:

- Add offered skills

- Remove offered skills

- Add wanted skills

- Remove wanted skills

Use the existing skills table instead of creating duplicate skills.

DATA SAFETY:

Use Supabase Row Level Security appropriately.

Users should only be able to modify their own profile and their own skill selections.

Do not use or expose Supabase service-role/secret keys in frontend code.

CODE QUALITY:

- Use reusable React components.

- Keep components organized and maintainable.

- Use TypeScript properly.

- Avoid unnecessary duplicate code.

- Keep the imported Stitch visual design intact.

- Make the application responsive for desktop and mobile.

FIRST IMPLEMENTATION PHASE:

For this first task, focus on making these parts fully functional:

1. Application routing

2. Supabase authentication

3. Register

4. Login

5. Logout

6. Protected routes

7. Admin route protection

8. Profile loading

9. Profile editing

10. Profile photo upload

11. Offered skills

12. Wanted skills

13. Availability

14. Public/private profile setting

Do NOT implement Smart Matching, Swap Requests, Notifications or Admin management functionality yet.

After implementing this phase, verify that the application builds successfully and that there are no TypeScript or runtime errors.

Do not make unrelated UI changes.
